# Code of Conduct

## Our Standard

Moj Džemat is a community publishing app, and contributions should reflect the same spirit: helpful, respectful, and careful with other people's time and trust.

Everyone participating in this project is expected to:

- use welcoming and respectful language
- give and receive technical feedback constructively
- stay focused on the work, the user experience, and the maintainability of the app
- be patient with people who are learning the codebase
- respect privacy, especially around admin accounts, emails, reset links, screenshots, logs, and production data
- disclose security concerns privately according to [SECURITY.md](.github/SECURITY.md)

Unacceptable behavior includes:

- harassment, insults, threats, or discriminatory language
- publishing someone else's private information without permission
- sharing secrets, session cookies, reset tokens, API keys, or production data
- intentionally disrupting issues, pull requests, CI, deployments, or production systems
- using the project spaces for spam, abuse, or unrelated promotion

## Scope

This code of conduct applies to all project spaces, including GitHub issues, pull requests, discussions, code review, commit messages, and any project-related communication.

It also applies when someone represents the project publicly, such as by discussing vulnerabilities, deployment behavior, or user data related to this repository.

## Reporting

If you see behavior that violates this code of conduct, report it privately to the repository maintainer ([@TajibSmajlovic](https://github.com/TajibSmajlovic)) with as much context as is safe to share. For security-related concerns, use GitHub's private vulnerability reporting as described in [SECURITY.md](.github/SECURITY.md) instead of a public issue.

Do not post sensitive personal details, private logs, reset links, session cookies, secrets, or exploit steps in a public issue.

## Enforcement

Maintainers may take any action they consider appropriate, including:

- asking for clarification or edits
- hiding, editing, or deleting comments
- closing issues or pull requests
- blocking users from further participation
- escalating security or abuse reports through GitHub

Enforcement decisions should be proportional, consistent, and focused on keeping the project safe and productive.
